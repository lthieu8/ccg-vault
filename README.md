# CCG BA Documentation

Single source of truth for what the team is building. Code answers *how*; this vault answers
*what* and *why*.

Open the parent folder as an Obsidian vault, or clone this repo on its own — every file is plain
markdown and nothing here requires Obsidian to read.

## Layout

| Folder | Holds | Who writes |
|---|---|---|
| `00-inbox/` | BA source documents, as delivered | BA only. Never edited after drop. |
| `02-specs/` | Validated specs. **The** source of truth. | BA, via `/ba-new` and `/ba-check` |
| `reports/` | Gap-check reports. Disposable. | Generated by `/ba-check` |
| `notes/glossary.md` | Domain vocabulary | Anyone, one definition per term |
| `notes/decisions.md` | Cross-cutting Q&A | Anyone who gets an answer from the BA |

## The one rule

**Only specs with `status: approved` are implementable.** Anything else is a work in progress and
developers should not build against it.

## Before you ask the BA anything

Search here first:

```bash
grep -ri "your question" 02-specs/ notes/
```

Most questions have been answered once already. When you get a new answer, write it into the
spec's Decisions section or `notes/decisions.md` — that is what stops the same question being
asked again next month. An answer given in Slack and never filed is an answer you will pay for
twice.

## Tooling

The `ccg-ba` Claude Code plugin drives this vault: `/ba-new`, `/ba-check`, `/ba-elicit`,
`/ba-approve` for the BA, `/dev-review` for developers. See the plugin README for setup.
